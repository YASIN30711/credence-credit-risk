04 · Model & system

Under the hood

What the system actually is — every claim below is verifiable in the code.

Inference model
A joblib-serialized scikit-learn pipeline (credit_risk_model.pkl) with preprocessing built in — it accepts the raw 11-field application record and returns class probabilities.
Decision threshold
Persisted separately in best_threshold.pkl and applied at inference: probability ≥ threshold → default predicted. The value is returned with every response, so results are always auditable.
Serving layer
FastAPI. The model and threshold load once inside the application lifespan and stay in memory; each POST /predict scores the request without re-reading the artifacts.
Request contract
A Pydantic-validated body of 11 typed fields — 7 numeric, 4 categorical — matching the model’s training schema.
Response contract
default_probability (0–1), default_prediction (0 or 1), threshold (float), and Result (“High Risk” or “Low Risk”).
Explainability
Every assessment is explained live: a native SHAP TreeExplainer scores each of the model's five XGBoost members for that exact applicant, and the averaged, ranked contributions (log-odds) are served through POST /explain.

  1. 1 Probability of default The model’s estimate that this applicant will default, on a 0–1 scale. It is a probability, not a verdict — 0.18 reads as an estimated 18% likelihood.
  2. 2 The decision threshold The classification flips at the tuned cutoff: a score at or above the threshold is predicted to default and labelled high risk. The threshold travels with every response, so every result can be checked.
  3. 3 The scope This is decision support, not underwriting. The model quantifies statistical risk; approving or declining a loan remains a human, policy-driven call.
